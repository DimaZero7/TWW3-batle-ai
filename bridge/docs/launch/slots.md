# Слоты: несколько игр сразу

[← Назад](README.md) · [Документация](../README.md) · [Запуск боя](run.md)

До трёх процессов игры одновременно для работы **под скриптом**: пробы, дорожки, бои ИИ против ИИ. Каждый процесс —
в своём слоте N = 1..3, со своими файлами; слот 0 — обычный одиночный запуск. Второй и следующие процессы проходят
проверку «уже запущена другая копия» своим ключом игры `-multirun` (разбор `tmp/farm/i1/REPORT.md`); слой защиты и
лицензии не трогается. Замер (8 отрядов, ×20; в это время шли экзамен на GPU и задача на CPU, `tmp/farm/m/REPORT3.md`):
две копии — 1,52× одной, три — 1,96×.

```bash
. ops/guard.sh; guard_take_slot 2 "lane a" || exit 1; trap 'guard_release_slot 2' EXIT
powershell -NoProfile -ExecutionPolicy Bypass -File bridge/launcher/launch.ps1 -Target nn-arena -Slot 2 -BuildDir build/aiai -Graphics low
powershell -NoProfile -ExecutionPolicy Bypass -File bridge/launcher/launch.ps1 -Target nn-arena -Slot 2 -ShowPlan   # только имена слота
```

`-BuildDir` — сборка слота (по умолчанию `build/<цель>`; не под `build/slots`). Её `manifest.target` обязан совпасть с
`-Target`; сборка под сетью (`own_ai net`, lock-step) или человека в слот не идёт; `-KeepGameOpen` со слотом — отказ.
Слот 0 `-BuildDir` не берёт; бой человека (`-Target human`) никогда не идёт в слоте и не получает `-multirun`.
`-ShowPlan` печатает имена и ничего не проверяет (замки, игру, HUMAN_PLAYING — нет).

## Что у слота своё

| Что | Слот 0 | Слот N |
|---|---|---|
| pack в `data/` | `tww3_bai_nn_arena.pack` | `tww3_bai_nn_arena_sN.pack` (`bridge/pack/slot.py`) |
| список модов | `tww3_bai_nn_arena_mods.txt` | `tww3_bai_nn_arena_mods_sN.txt` |
| файлы нашего Lua в папке игры | `tww3_bai_<x>.<ext>` | `tww3_bai_<x>_sN.<ext>` |
| метка установленного | `build/launcher-installed.json` | `build/launcher-installed.sN.json` |
| сборка и прогоны слота | `build/<цель>/runs/<время>` | `build/slots/sN/<цель>/`, прогоны в `.../runs/<время>-sN` |
| замок | `state/probe_game.lock` | `state/probe_game.N.lock`, токен в `BAI_SLOT_LOCK_HELD_N` |
| рабочий стол | пользователя | отдельный `WinSta0\tww3_bai_sN` (ничего не видно и не шлётся на стол пользователя) |
| ключ игры | — | `-multirun` |

Pack слота — pack сборки (его SHA-256 сверен с манифестом, прочитанным один раз) с прослойкой в начале каждого
Lua-файла: она переименовывает файлы `tww3_bai_*` без папки (и `./tww3_bai_*`, в любом регистре) в `io.open`,
`io.lines`, `io.input`, `io.output`, `os.rename`, `os.remove`; Lua с именем `tww3_bai_` внутри папки — отказ при сборке.
Pack в `data/` копируется под именем `*.tww3_bai_part`, сверяется и только потом переименовывается.

## Что общее — «сеанс слотов»

Файл настроек игры и пакеты Workshop в `data/` общие для живых слотов. Их ведёт `bridge/launcher/slots.ps1`, запись —
`build/slot-session.json` (пишется целиком: временный файл, сброс на диск, замена). Участник — один запуск: id, PID и
время старта launcher'а, PID + время старта + путь его игры. Каждый launcher держит мьютекс `Global\tww3_bai_launcher`,
пока проверяет, резервирует, ставит и запускает, и пока убирает; одиночный запуск — весь свой прогон. Мьютекс
отдаётся в `finally` всего скрипта — и после Ctrl+C в оставшейся открытой консоли; мьютекс, который нельзя открыть
(другой пользователь, повышенный процесс), — отказ с объяснением.

- **Резерв первым делом**: слот записывается в сеанс до любого своего файла; занятый слот, чужая игра, другая графика
  или другие зависимости — отказ, ничего не тронуто.
- **Первый входит**: сначала приводит в порядок мёртвый сеанс и упавший одиночный запуск (настройки пользователя
  назад, затем их файлы); копирует настройки во временный файл, сверяет, пишет его SHA-256 в сеанс, переименовывает в
  `build/preferences.slots.backup.txt` и только тогда пишет «Нормальную» и графику.
- **Последний выходит**: если не запущена ни одна игра — возвращает настройки (только копию с записанным хешем;
  записано, сброшено, сверено, потом копия удаляется), затем убирает общие файлы и файлы всех слотов. Если какая-то
  игра ещё идёт — копия и сеанс **остаются**, вернёт следующий запуск или `bridge/launcher/cleanup.ps1`; launcher
  выходит с кодом 3. Копия без записи в сеансе или с другим хешем — отказ, обе копии остаются. Сеанс помнит и хеш
записанной «Нормальной»: если файл сейчас не копия, не наша запись и в нём уже нет наших значений (пользователь
поменял сам) — отказ, оба файла остаются; так же `cleanup.ps1` с упавшим одиночным запуском.

Общими остаются файлы самой игры, «последний пишет» (`lua_mod_log.txt`, `mp_log.txt`, `gfx.log.txt` и др.); их читает
только человек. Новый отчёт в общей папке `crash_report` слот не берёт как свой: копия в прогон как
`unattributed_*`, статус `process_exited`. Счётчик `tww3_bai_sequence_sN.txt` остаётся в папке игры.

## Охрана и замки

- `state/HUMAN_PLAYING` — ни один слот не стартует; проверяется ещё раз под мьютексом прямо перед стартом, а во
  время боя — каждую секунду: слот закрывает СВОЮ игру, статус `human_playing`.
- Замки (`ops/guard.sh|ps1|py`, одно правило): вход — только исключительным созданием файла; замок всей игры берёт
  `probe_game.1/2/3.lock`, потом `probe_game.lock` и держит все слоты; мёртвый держатель (токен `... pid <pid> id <8
  hex>` без такого процесса или пустой файл старше 60 с) снимается только под `<замок>.break`; жив ли процесс, bash
  спрашивает у Windows (`tasklist`). Мёртвые замки слотов не считаются занятыми и в проверках «свободна ли игра».
- Одиночный запуск отказывает при живом замке слота не своего замка всей игры и при живом сеансе.
