# Серия боёв в одном процессе игры

[← Назад](README.md) · [Документация](../../README.md) · [Время загрузки](loading-times.md)

Как сыграть несколько боёв подряд, не перезапуская WH3: после конца боя скрипт сам
нажимает «переиграть» на экране результата. Проверено в игре 25.09.2026 на прежнем
стенде дуэлей: два отряда коссаров в своём XML-сценарии, свой Lua-мод, сторонние моды
не нужны. Сам стенд удалён 30.09.2026; здесь осталось то, что он узнал об игре.

## Что проверено

- Три завершённых боя подряд в одном процессе WH3 и два автоматических
  подтверждения переигровки.
- Повторная загрузка того же боя ≈ 11 с, первая загрузка ≈ 83 с
  ([время загрузки](loading-times.md)). Сам бой длился 7–8 с.
- Скорость: запрошено x40, измерено x25–28 (игровое время, делённое на реальное
  время внешнего наблюдателя). Загрузки в это время не входят.
- Между боями менялся внешний Lua-файл в папке игры: следующий бой прочитал новую
  версию без пересборки pack (две версии за серию). Изменения самого pack или XML
  требуют пересборки и нового запуска игры.

Нынешние цели launcher запускают по одному бою на процесс игры: у арены нейросети
загрузка ≈ 90 с, бой на x20 — 25–45 с реального времени.

## Как скрипт переигрывает бой

1. Бой закончился с результатом от движка. Скрипт явно завершает фазу победы:
   `bm:end_battle()`.
2. Раз в 0,5 с реального времени (`bm:real_callback`) скрипт ищет экран результата
   `in_battle_results_popup` и на нём кнопку `button_rematch`. Когда оба видны и
   кнопка не `inactive`, нажимает её через UI API игры: `SimulateLClick()`. Мышь и
   внешнее управление не нужны. Ожидание ограничено 30 с.
3. Появляется подтверждение `dialogue_box`. Скрипт проверяет текст `DY_text`
   («переиграть эту битву» в русском интерфейсе; другие языки не проверялись) и
   нажимает `both_group` → `button_tick`. Ожидание ограничено 10 с.
4. Карта загружается заново, и мод запускается с начала. Что нужно следующему бою
   (номер боя в серии и т. п.), скрипт до `end_battle()` пишет в файл в папке игры и
   читает в начале следующего боя. Файл очищается сразу после чтения, чтобы падение
   не устроило бесконечный цикл.

```lua
local popup = find_uicomponent(core:get_ui_root(), 'in_battle_results_popup')
local button = popup and find_uicomponent(popup, 'button_rematch')
if popup and popup:Visible() and button and button:Visible()
        and button:CurrentState() ~= 'inactive' then
    button:SimulateLClick()
end
-- через 0,5 с, пока не появится подтверждение:
local dialog = find_uicomponent(core:get_ui_root(), 'dialogue_box')
local label = dialog and find_uicomponent(dialog, 'DY_text')
local yes = dialog and find_uicomponent(dialog, 'both_group', 'button_tick')
if dialog and dialog:Visible() and label and yes and yes:Visible() then
    -- сначала проверить label:GetStateText()
    yes:SimulateLClick()
end
```

## Что не сработало и тонкости

- `bm:restart_battle()` в бою, запущенном из XML, нового боя не начал. Команда CCO
  RestartBattle — тоже.
- В игровой Lua `string.find` заменён вариантом для UTF-8. Для точного побайтового
  поиска текста есть исходная функция `string.find_lua`.
- Переигрывать только после итогового результата движка. Ошибки и тайм-ауты не
  повторять в цикле и не считать поражением.
- Работает настоящий процесс WH3 с графикой; публичного движка без графики не найдено.
- Серия боёв проверяет цикл, но не доказывает независимость случайных исходов и
  сохранение свойств боя на высокой скорости.
