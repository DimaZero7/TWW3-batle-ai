# WH3 Battle AI: автоматический испытательный стенд

Собственный Lua-мод управляет двумя отрядами коссаров в фиксированном XML-сценарии.
Стрельба выключена; оба отряда получают приказ ближней атаки. Сторонние игровые моды
не требуются. Это проверка управления, не готовый тактический ИИ.

Выбранный режим: три последовательных боя в одном процессе WH3, скорость x20.
Между боями карта загружается заново; приложение не перезапускается. Пока повторяется
один сценарий. Смена составов между боями ещё не реализована.

Проверено в игре 25.09.2026: три завершённых боя в одном процессе, два автоматических
подтверждения переигровки и две версии Lua. На заданных x40 измерено x25–28;
повторная загрузка примерно 11 с, бой 7–8 с. Доказательства и ограничения.
[Проверка ускорения загрузки](loading-times.md).

## Запуск

WH3 должна быть закрыта. Запускатель использует отдельный tww3_bai_mods.txt;
выбор модов кампании в used_mods.txt остаётся нетронутым.
Команды из каталога репозитория; установка требует записи в каталог игры:

```powershell
python tools/build.py --runs 3 --speed 20 --timeout 300
& ./tools/install.ps1
& ./tools/launch-duel.ps1 -Watch -CloseWhenDone -NextPolicy scenarios/policies/delayed_melee.lua
```

При необходимости передать -Python с полным путём к python.exe.
Перед каждым запуском графика автоматически настраивается. Сохраняется резервная
копия preferences в build/, устанавливаются
минимальное качество и размер отрядов Ultra (gfx_unit_size 3); вступительный ролик выключается. Разрешение и сложность
не меняются. XML отдельно задаёт 120 бойцов на сторону; ранние опыты использовали 90.

Запускатель передаёт путь XML и tww3_bai_mods.txt, сверяет SHA-256 установленного архива,
записывает PID и начальное смещение журнала. Создание процесса не считается успешным боем.
-NextPolicy проверяет обновление кода: после старта первого боя наблюдатель атомарно
заменяет внешний Lua-файл. Следующий бой читает новую версию. Диагностическая политика
ждёт до десятой секунды модельного времени; в журнале появляется warmup_10s.
После серии исходный файл восстанавливается, если никто другой его не изменил.
-CloseWhenDone закрывает только запущенный этим вызовом процесс после серии или ошибки.

## Цикл

1. Прямой запуск XML с фиксированными составами и расстановкой.
2. Проверка режима, сценария, состава и автоматическое завершение расстановки.
3. Чтение внешней политики tww3_bai_policy.lua; запрос и подтверждение управления.
4. Приказы, журнал состояний и результат, определённый движком.
5. Явное завершение фазы победы, ожидание экрана результата.
6. Вызов Lua-обработчика button_rematch и подтверждение переигровки через dialogue_box.

Последний шаг использует игровой API без внешнего управления мышью и Computer Use.
Обычный bm:restart_battle() в диагностическом XML-запуске не привёл к новому бою.
Ожидание экрана ограничено 30 секундами; наблюдатель также ограничивает общее время
и обнаруживает отсутствие событий. Ошибки и тайм-ауты не считаются поражением.

Параллельный эксперимент `triple_melee` отложен по решению пользователя и не входит
в текущую сборку. Его исходники сохранены только как история исследования.

## Результаты

В reports/<дата-время>/ сохраняются:

- launch.json: PID, сборка, SHA-256 архива, время запуска, смещение журнала.
- events.jsonl: игровые события и отметки времени внешнего наблюдателя.
- policy-initial.lua, policy-next.lua: точные версии кода эксперимента.
- watch.json: итог серии, число боёв и SHA-256 политик.
- summary.csv, report.html: исходы, потери, приказы, измеренная скорость.

Первичный журнал находится рядом с Warhammer3.exe: tww3_bai_events.jsonl.
Повторная обработка: python tools/report.py <events.jsonl> --output <каталог>.
engine_speed — настройка движка; measured_speed — модельное время / реальное время
наблюдателя. Загрузки карты не входят во время боя. В ранних журналах без wall_iso
значение duration_wall_s неточно из-за представления epoch-секунд в игровой Lua.

## Разработка

src/policy.lua — чистая логика, src/harness.lua — адаптер и цикл. Политику можно
заменять внешним файлом перед следующим боем без пересборки pack. Изменения адаптера
или XML требуют пересборки и повторного запуска приложения.

```powershell
python -m pip install --only-binary=:all: --target .tools/python -r requirements-dev.txt
python -m unittest discover -s tests -v
python tools/build.py --runs 3 --speed 20
```

Тесты Lupa/Lua 5.1 проверяют контракты и ошибки, но не симулируют механику WH3.
После тестов пересобрать нужную конфигурацию: тест сборщика создаёт контрольный pack.
Стенд отвергает кампанию, мультиплеер, повторы, квестовые, учебные, осадные и засадные
бои. Ручной пользовательский бой допускается с одним пешим лордом на сторону.
Для обычной игры не добавлять тестовый pack в список модов кампании.

## Ограничения

Работает настоящий процесс WH3 с графикой; публичный headless-движок не найден.
Повторные дуэли проверяют стенд, но не доказывают качество тактики, независимость
случайных исходов или сохранение свойств боя на высокой скорости.
Исследование: docs/battle-test-harness-research.ru.md.

Источники: [Battle Manager](https://chadvandy.github.io/tw_modding_resources/WH3/battle/battle_manager.html),
[Unitcontroller](https://chadvandy.github.io/tw_modding_resources/WH3/battle/battle_unitcontroller.html),
[PFH5 RPFM](https://github.com/Frodo45127/rpfm/blob/v5.0.6/rpfm_lib/src/files/pack/pack_versions/pfh5.rs).
