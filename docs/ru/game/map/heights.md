# Высоты земли и построение карты высот

[← Назад](README.md) · [Инструкция по карте](README.md) · [English](../../../en/game/map/heights.md)

**Высоту земли мы уже читаем из игры.** Карта высот — эти же числа, разложенные
по положениям X/Z. Чтение высот проверено; что из высот следует для боя
(позиции, движение, видимость), здесь не исследовалось.

## 1. Получить высоту точки из игры

```lua
local x, z = reader.cell_center(grid, ix, iz)
local y = bm:get_terrain_height(x, z)
```

X и Z задают положение на плоскости. Ответ — число: мировая высота Y в метрах.
Это не высота над отрядом, не расстояние от самой низкой точки карты и не
установленный уровень моря. Сохраняем число как вернула игра. Отрицательная
высота сама по себе не ошибка. Пропуск, нечисловой или бесконечный ответ — ошибка,
а не земля на нулевой высоте.

Именно этот вызов находится в [reader.read_batch](../../../../src/apps/map/).
Затем модуль создаёт вектор `(x,y,z)` для отдельных запросов типа земли и
ограничений области. Читаем порциями; текущий сборщик использует 4 096 клеток за
вызов на паузе расстановки. Его время включает три запроса и запись CSV —
**это не отдельный замер скорости чтения только высоты**.

## 2. Собрать числа в таблицу

Получаем рамку мини-карты и выбираем шаг `s`: см. [координаты](coordinates.md)
и [границы](boundaries.md). Номера строк и столбцов начинаются с нуля:

```text
x = min_x + (ix + 0.5) * s
z = min_z + (iz + 0.5) * s
H[iz, ix] = высота_земли(x, z)
```

В таблице `H` строки идут вдоль Z, столбцы — вдоль X. Нулевая строка начинается
у `min_z`, нулевой столбец — у `min_x`. Измеряем **центр клетки**. Если закрасили
весь квадрат одним цветом, это ещё не означает, что земля внутри него плоская.

Первоначальный gzip CSV содержит `ix,iz,height,clear,ground_id`; новый сборщик
также записывает X/Z и тип земли строкой. В обоих вариантах высота сохраняется с
шестью знаками после запятой. Это точность записи файла, а не доказательство
микрометровой точности поверхности. Рядом нужны границы, начало, шаг, размеры,
сценарий и хеши источников. Одних номеров клеток недостаточно для масштаба карты.

В сохранённом замере Кислева 1 м: границы X/Z `[-512,512]`, таблица `1024×1024`,
центры от `-511.5` до `511.5`. Это параметры конкретного сценария, не всех карт.

## 3. Построить изображение без игры

[heightmap.py](../../../../tools/analysis/heightmap.py) читает CSV или gzip CSV.
Проверяет индексы, повторы, пропуски и корректность высот. Если есть столбцы X/Z,
сверяет их с переданной сеткой. Границы и шаг берём из сведений о замере.
Старый CSV без X/Z не позволяет независимо проверить правильность этих параметров.

Скрипт сохраняет числовую таблицу float64 в `height.npy`, описание и хеши в JSON,
а также PNG на английском и русском. Таблица сохраняет числа из CSV, но не
восстанавливает знаки, потерянные при записи исходного CSV.

На изображении X направлен вправо, Z — вверх (`origin="lower"`). Используем
размер всей сетки запросов, затем обрезаем рисунок по рамке мини-карты. Цвет
соответствует мировой Y; справа подписана шкала. Сглаживания между замерами нет
(`interpolation="nearest"`). При уменьшении картинки клеток может быть больше,
чем экранных пикселей: отдельные значения нужно читать из таблицы.

Цвет означает **только высоту**: тёмное ниже, светлое выше. Он не означает воду,
лес, безопасный путь или препятствие. Шкала выбирается для конкретного набора;
перед сравнением цветов разных карт нужно установить одинаковую числовую шкалу.

## 4. Повторить пример без запуска WH3

Из корня репозитория, Python проекта (`numpy`, `matplotlib` из `requirements-dev.txt`);
исходная сетка — локальный архив:

```bash
.venv/Scripts/python -m tools.analysis.heightmap --csv research/evidence/map-data/kislev-scales-evidence/grid-1m.csv.gz --bounds -512 512 -512 512 --step 1 --output build/map-research/heightmap-1m
```

Можно передать и `tww3_bai_map_capture_grid.csv` завершённого нового замера,
указав рамку и шаг именно того опыта. Скрипт не запускает игру и не отдаёт Lua-команд.
Результаты и воспроизводимый NPY остаются в игнорируемой `build/`.

и `проверка` (локальный архив: `research/evidence/map/heightmap-kislev-1m/validation.json`). Новый запуск игры не потребовался.

## 5. Правила для будущих агентов

- Решения принимаем по числам и метровым координатам, не по цветам PNG.
- Разность высот двух измеренных позиций: `y2-y1`. Наклон можно оценить как
  `atan2(y2-y1, расстояние_по_горизонтали)`. Это средний уклон между замерами,
  не готовый штраф движения от игры и не самый крутой участок между точками.
  Связь уклона со скоростью здесь не проверена.
- Шаг 1 м — частота наших измерений, не доказанный размер сетки движка.
- Одна Y на каждую X/Z не описывает несколько этажей: настил моста и землю под
  ним, крыши, навесы и пути летающих отрядов.
- Высота не показывает деревья, объёмы препятствий, глубину воды или видимость.
  Тёмную низину на изображении нельзя объявить рекой только по цвету.
- Игра возвращает высоту и за рамкой мини-карты. Так границу не определяем.
- Высота, тип земли и ответ об ограничениях — разные данные. По одной высоте
  нельзя установить проходимость, линию обзора или боевые бонусы.
- Повторное использование относится к записанному сценарию до новой проверки.
  Изменяемый рельеф, другие варианты карты и версии игры не проверены.
