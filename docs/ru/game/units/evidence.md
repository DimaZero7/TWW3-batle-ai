## Условия

- `basic-rank1`, `withdraw-rank1`: официальная полевая карта `chokepoint_badlands_river`, сухой день, без осады. `passives-rank1`: `wh3_main_macro_ksl_plains_01`, именно вариант `catchment_04`. Другой вариант той же карты даёт другие лесные зоны.
- Итоговый генерал: `is_commanding_unit() == true`, CCO `HasCharacterRank == true`, `CharacterRank == 1`, `ExperienceLevel == 0`. В ранних базовых опытах и сравнениях обороны/натиска использован тот же пеший тип, но без объявления генералом: он возвращал роль некомандующего и уровень 0. Эти наборы выделены отдельно и не подтверждают прокачку персонажа кампании.
- Три исследуемых отряда и союзный резерв; три вражеских отряда копейщиков и резервный генерал. Для натиска цели заменены на три отряда по 60 рыцарей Империи. Несколько разнесённых дорожек находятся в одном бою. Это изолированные опыты с командами, не соревнование полноценных армий.
- Обе стороны под управлением скрипта. Телепорты используются для расстановки и разделения этапов; только в проверке обороны противника принудительно обращали в бегство. Бессмертие, восстановление здоровья/стрел/усталости, выдачу атрибутов и принудительную невидимость не применяли.
- После расстановки позиции задаются заново: движок может изменить координаты из XML. В боевых этапах урон и мораль естественные. Случайное зерно не фиксировали; один прогон не является статистическим исследованием баланса.
- Минимальная графика, размер Ultra, только диагностический скриптовый pack. Поэтому версия игры помечена `modded`.

## Наглядные результаты

### Стрельба и преследование

![Боезапас и смещение при преследовании](../../../../research/evidence/units/empire-20260926/controls.png)

Верхний график — `basic-rank1`. Расход стрел по этапам: целевая стрельба **282**, выключение свободного огня без отмены цели **158**, остановка + выключение **0**, свободный огонь **199**, финальная остановка + выключение **0**. В предыдущих повторениях после остановки завершалось ещё 0–4 выстрела. Нулевой хвост одного опыта не гарантирует мгновенного прекращения всех выстрелов.

Нижний график — сравнение `guard-on` и `guard-off`: смещение между началом и концом 35 секунд после бегства цели. Это не длина всего пройденного пути. Принудительное бегство цели отдельно отмечено в логах.

### Геометрия строя

![Позиции бойцов при разной ширине строя](../../../../research/evidence/units/empire-20260926/formations.png)

В `withdraw-rank1` запросы `ManList.Size` и `ManList.At(i).Position` дали координаты отдельных бойцов. `Position` возвращает несколько чисел X/Y/Z, а не Lua-объект вектора. Снимки сделаны в конце этапов.

| Отряд | Приказ 15 м: размах по Z | Приказ 50 м: размах по Z |
|---|---:|---:|
| 120 копейщиков | 13,553 м | 47,344 м |
| 90 лучников | 13,980 м | 48,427 м |
| Генерал, в обоих случаях приказ 5 м | 0 | 0 |

Направление — 90°, поэтому поперёк фронта измеряется Z. Здесь **центры бойцов**, без радиуса моделей, оружия и физических оболочек. Ширина приказа и размах центров — разные величины. Перестроение подтверждено, универсальная модель занятой площади и столкновений ещё не получена.

### Отход и поддержка

В `withdraw-rank1` состояние CCO `IsWithdrawing` появилось у всех на первом опросе после приказа — через 0,5 игровой секунды. `is_leaving_battle` стало истинным через **63,5 / 113,5 / 70,5 секунды** у копейщиков/лучников/генерала. Проверка завершилась, когда уход подтвердили все трое. Это подтверждение процедуры выхода и флагов; сохранение армии и потери после боя в кампании не проверены. `withdraw(false)` также привёл к отходу в `passives-rank1`; основной рецепт использует бег.

В `passives-rank1` последовательность «генерал далеко → рядом → далеко» изменила долю боевого духа копейщиков **1,0833 → 1,2167 → 1,0833**, лучников **1,1000 → 1,1600 → 1,1000**. Hold the Line получили ближайшие копейщики, лучники — нет. Это значения чтения, не формулы отдельных бонусов.

## Сохранённые материалы

`Индекс прогонов` (локальный архив: `research/evidence/units/empire-20260926/runs.json`) · `Хеши SHA-256` (локальный архив: `research/evidence/units/empire-20260926/hashes.json`) · `Выборка установленной БД` (локальный архив: `research/evidence/units/empire-20260926/installed-db-selection.json`)

В папке каждого набора есть `events.jsonl.gz`, `analysis.json`, точный исполненный `capture.lua`, входной и экспортированный XML, манифест сборки и записи запуска/завершения/очистки. В событиях сохранены свойства отрядов, расстановка, этапы, состояния, приказы способностей и окончание опыта.

Lua-таблицы с числовыми ключами записаны как JSON-объекты, не массивы. `ms` — время боя, `elapsed` — время от начала этапа, `wall` — UTC с точностью до секунды. Первая запись этапа может отражать состояние на границе приказа; для подробного анализа смотреть исходный лог и `elapsed`.

Выборка БД получена до игровых опытов с побайтовой проверкой обратной сборки. Это доказательство записей игры, не замер коэффициентов урона. Бинарники игры и сами оригинальные pack-файлы не публикуются. Снимки сборщика, анализатора и построения графиков сохранены; повторение ниже использует **точный скрипт каждого прогона**, а не его пересборку более поздней версией исходников.

## Повторить опыт

Из корня репозитория, через Python проекта с имеющейся зависимостью Lupa в `.tools/python`:

```powershell
python -X utf8 tools/unit-actions/replay.py basic-rank1
if ($LASTEXITCODE -ne 0) { throw 'Build failed' }
./tools/map-capture/launch.ps1 -TimeoutSeconds 240
```

[Сборщик повторов](../../../../research/scripts/unit-actions/replay_tool.py) проверяет хеши архива, компилирует Lua 5.1, собирает PFH5, проверяет чтение обратно и требует **совпадения хеша pack с исходным прогоном**. Сам ничего не устанавливает и не запускает. Другие названия опытов перечислены в `--help`.

[Запускатель](../../../../tools/launcher/launch.ps1) устанавливает диагностический pack, запускает один бой, сохраняет данные и закрывает только свой игровой процесс при завершении, ошибке или тайм-ауте. [Завершение](../../../../tools/launcher/launch.ps1) проверяет сохранённые файлы перед очисткой. Нажимать кнопки интерфейса не требуется.

Замеры карты и отрядов **используют одну папку сборки и одно имя служебного pack**. Перед запуском собирать нужный опыт, одновременно их не запускать. Формальный grid CSV в опытах отрядов нужен для совместимости запускателя; измерением карты он не является.

После ошибки служебные файлы могут остаться для диагностики: сначала сохранить частичные результаты, затем очищать. Незавершённый опыт не считать успешным. Проверки отхода завершаются досрочно по флагам ухода: после конца боя игровые таймеры могут перестать работать.
