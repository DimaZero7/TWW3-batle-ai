Решение пользователя 28.09.2026. **Сделано 28.09.2026** — как пользоваться: [Проигрыватель боя](../../launch/viewer.md). Основа — [ai-design, 7.5](../ai-design.md#75-графическая-оболочка).
Живая трансляция (вариант 2) — позже, когда у симуляции будет движение по времени.

| Пункт | Что |
|---|---|
| Над чем работаем | Веб-страница, которая проигрывает **запись боя** в реальном времени (1×), с паузой, ×2/×5 и перемоткой; что показывать — выбирается заранее |
| Модули | новые: `tools/viewer/` (запись → формат проигрывателя, страница), запись боя из симулятора (`tools/sim/formation.py`) и из игровых прогонов (`build/*/runs/*/events.jsonl`) |
| Что должна уметь симуляция | Писать запись по времени: положения отрядов (и бойцов для показа строя) по тикам, решения ствола, окно, стрелы и потери. Своего движения по времени у симуляции нет — в первой версии плавная интерполяция между положениями до и после манёвра по времени ходьбы |
| Какие реальные данные нужны | Новых нет: игровые прогоны уже пишут отряды и бойцов (`approach_sample`, `hold_sample`, `stage_snapshot`), врага с `--enemy-ai`, решения (`approach_decision`) |
| Как поймём, что работает | Один и тот же бой (`window_game`) из игры и из симуляции проигрывается рядом; видно выравнивание, скачки, окно, перестрелку; слои включаются набором |

## Что показывать — слои

| Слой | Что рисует | Откуда |
|---|---|---|
| `blocks` | рамки отрядов, цвет стороны, значок типа | положения, ширина, глубина |
| `soldiers` | точки бойцов | `soldiers_dm` (игра), раскладка в рамке (симуляция) |
| `reach` | дуги дальности стрелков | `apps.reach` |
| `window` | окно: где мы достаём, где они | решения ствола |
| `path` | след скачков и цели манёвров | решения ствола |
| `decisions` | подпись решения («выравниваюсь», «стою в окне», «под обстрелом») | `approach_decision` / журнал ствола |
| `losses` | бойцы и стрелы по времени | `hold_sample`, перестрелка симуляции |
| `mask` | где нельзя встать | маска |
| `enemy` | враг (только то, что видим) | видимые отряды |

**Наборы** (выбор заранее): `approach` = blocks, path, window, decisions, enemy;
`fire` = blocks, soldiers, reach, window, losses, enemy; `debug` = всё. Набор —
параметр запуска или галочки на странице.

## Формат записи (предложение)

Один JSON на бой: `meta` (карта, стороны, откуда запись), `frames` — по тикам
`{t_ms, units: [{id, side, role, x, z, bearing, front_m, depth_m, men}], soldiers?,
decision?, window?}`. Страница — один HTML без сервера (открыть файлом),
Canvas, данные рядом или встроены.

## Порядок

1. Формат записи и конвертер игровых прогонов (`window_game`) — на готовых данных.
2. Страница: слои, наборы, 1×, пауза, скорость, перемотка.
3. Запись из симулятора (интерполяция манёвров) — тот же бой рядом с игрой.
4. Документация (раздел в дереве или `tools`), тесты конвертера.

После неё — исправление выравнивания (№ 26).

## Итог (28.09.2026)

Сделаны все 4 шага. Код: `tools/viewer/` (`record.py` — формат и проверка, `game.py`, `sim.py`, `player.html`,
`python -m tools.viewer game|sim|compare|page`). Проверки: `tests/tools/test_viewer.py` (12).

Что вышло иначе, чем в предложении:

- `units` вынесены из кадров: сторона, роль, `men_max`, `reach_m` не меняются и пишутся один раз; в кадре —
  только то, что меняется.
- `(x, z)` в записи — **центр** блока, как даёт игра. Симулятор хранит центр переднего ряда, конвертер
  сдвигает на половину глубины.
- Бойцы игры — снимки в системе отряда: они едут вместе с отрядом между снимками (снимки есть только в
  `stage_snapshot` и в конце манёвров).
- Простой в игре (этап маски — 54 с) вырезается до секунды, часы боя (`game_ms`) сохраняются.
- Ссылка на момент: `viewer.html#preset=fire&t=300`.

Что видно на `window_game` (игра 20260928-150819 и симуляция рядом):

- в игре армия почти 3 минуты выравнивается и крутится, пока враг перестраивается, в симуляции враг стоит,
  и армия сразу идёт скачками (это № 26);
- в перестрелке симуляция убивает заметно больше, чем игра (урон стрелами сверить в фазе 3).

## Расширение (28.09.2026): модули ИИ и понятность

Просьба пользователя: в симуляции видеть каждый модуль, который можно проследить (поле между нами и
врагом, группы и т. д.), отдельно — обход препятствия группами. И «непонятно, какие отряды участвуют,
что вообще происходит». Не забыть про два языка.

Новых реальных данных не нужно: всё уже считают модули в симуляции.

Сделано:

- **Слои модулей:** поле боя (`apps.battlefield`), группы (`apps.vision`), выравнивание
  (`apps.alignment`), пути лорда (`apps.formation`), очереди (`apps.logistics`). Запись хранит их на каждое
  решение (`overlays`), набор «модули ИИ».
- **Обход препятствия:** `python -m tools.viewer logistics <армия>` — движение шагом 0,5 с по приказам
  диспетчера, с очередью и все сразу рядом, давка и бойцы на камнях на графике.
- **Понятность:**
  - метки отрядов (П1, С3, Лорд) по классу отряда;
  - подсказка при наведении;
  - список отрядов с бойцами и тем, что делает каждый;
  - смысл этапа простыми словами;
  - «Что на карте» — объяснение каждого включённого слоя.
- **Два языка:** все тексты записи — `{ru, en}`, переключатель RU/EN на странице, документация на обоих.
- Запись — версия 2. Симулятор хранит в манёвре, что видели модули до него и где встала армия
  (`tools/sim/formation.py`). Ходок очередей отдаёт ряды давки (`tools/sim/logistics.py`). Эталоны не
  изменились.
