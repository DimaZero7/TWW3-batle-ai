# Задача: отряд обходит препятствия, не застревая

[Архитектура ИИ](../ai-design.md) · [Порядок работы: карточка задачи](../ai-design.md#8-порядок-работы-карточка-задачи)

> **Статус:** этап 1 (анализ карты) сделан 27.09.2026; этап 2 предложен.
> Первая задача ИИ. Отметки о ходе работы — в [журнале](#журнал).

## 1. Цель

Один отряд пехоты получает цель за препятствием и приходит туда **без
застреваний**: не выстраивается в очередь в узком месте, не упирается в углы,
не встаёт «афк».

### Почему это проблема

Движок прокладывает путь для **центра отряда** и не проверяет, пройдёт ли
**строй целиком**. Широкий строй ведут через узкий проход, бойцы выстраиваются
в очередь, толкаются и застревают в углах. Это известная проблема Total War,
особенно при осадах. Опытный игрок решает её вручную: ведёт отряд узким строем
через промежуточные точки. Простой приказ «встань за препятствием» не подходит.

### Что делаем

Свой планировщик **на уровне строя** (не бойца): маршрут по коридорам, где
строй помещается, цепочка промежуточных точек с шириной и направлением,
сужение перед узким местом и расширение после, проверка конечной позиции,
распознавание застревания и выход из него. Отдельных бойцов по-прежнему ведёт движок.

### Границы

| Входит | Не входит (позже) |
|---|---|
| Один отряд пехоты | Несколько своих отрядов (заторы между своими) |
| Статичные препятствия: здания, скалы, лес, объекты | Осады, стены, ворота, лестницы |
| Карта The Moorlands Route (`catchment_03`), случаи T0–T5 | Другие карты (проверим после) |
| Без противника | Движение под обстрелом и рядом с врагом |
| | Конница, монстры, артиллерия |

## 2. Определения

| Термин | Определение (пороги уточняются на этапе 3) |
|---|---|
| **Препятствие** | Клетка, куда отряд не может встать (по карте проходимости этапа 1) |
| **Запас места** клетки | Расстояние от клетки до ближайшего препятствия, м |
| **Проход** | Участок пути, где запас места меньше половины текущей ширины строя плюс допуск |
| **Дошёл** | Центр отряда не дальше `R` м от цели (старт: 5 м), направление отличается не больше чем на 15°, отряд не движется |
| **Застрял** | Приказ на движение есть, отряд не в бою, за `T` с (старт: 10 с игры) центр сдвинулся меньше чем на `D` м (старт: 2 м) |
| **Наивный приказ** | Один приказ «идти в точку цели» с исходной шириной строя, без промежуточных точек |

### Этап 1. Анализ снятой карты — ✅ сделан

Инструмент `tools/analysis/obstacles.py`, результат и выводы —
[research/analysis/moorlands-obstacles](../../../../research/analysis/moorlands-obstacles/README.md).

Главное:

- препятствий по `is_area_clear` — **10 крупных скальных групп** (42–114 м);
- **узких проходов между ними нет** (минимум 72 м);
- есть **вогнутые «углы»**: Г-образный, подкова, полумесяц;
- **заборы** (292 секции, 29 линий) `is_area_clear` почти не видит; просветы
  между их линиями **3,6–4,2 м** — настоящие узкие проходы, *если заборы мешают движению*;
- пробелы в данных: достижимость по клеткам, мешают ли заборы, сетка 1 м
  около тестовых мест, размеры строя.

### Этап 2. Тестовые случаи и нужные данные — предложение

| Случай | Место | Что проверяет |
|---|---|---|
| T0 | Открытое поле без препятствий | Контроль: наивный приказ и наш маршрут должны вести себя одинаково |
| T1 | Группа 7, Г-образный угол (264; 35) | Обход угла, цель за внутренним углом |
| T2 | Группа 9, подкова (216; 180) | Старт внутри подковы, цель за её закрытой стороной — классическая ловушка |
| T3 | Группа 4, полумесяц (−221; −103) | Обход вогнутой стороны |
| T4 | Просвет в заборах ≈3,6 м (12,7; −32,4) | Узкий проход: строй шире прохода |
| T5 | Просвет в заборах ≈4,2 м (31,7; −6,2) | Второй узкий проход для повторяемости |

Нужные данные (только для этих случаев):

| Данные | Откуда | Для чего |
|---|---|---|
| Сетка 1 м в окнах ~120 × 120 м вокруг T1–T5: `is_area_clear`, `can_reach_position` для пехоты | Прицельный прогон `map-capture` по окнам (этап 4) | Точная карта препятствий и проверка, что `is_area_clear` = «нельзя пройти» |
| Мешают ли заборы движению | Один опыт: отряд через линию забора (этап 4) | Есть ли на карте узкие проходы |
| Размеры строя: фронт и глубина от ширины, минимальная ширина, время перестроения | Опыт с копейщиками (этап 4) | Прямоугольник строя в симуляции и алгоритме |
| Поведение движка при наивном приказе в T1–T5 | Опыт (этап 4) | Подгонка модели затора |

Пока нет данных из игры, симуляция v0 строится на сетке 3 м, а неизвестное
(мешают ли заборы, размеры строя) задаётся **явными параметрами-допущениями**,
которые этап 4 заменяет измерениями.

### Этап 3. Симуляция v0 и просмотрщик

| Шаг | Что делаем | Результат |
|---|---|---|
| 3.1 | Сетка препятствий по окнам T0–T5; отряд как прямоугольник строя; движение со скоростью; модель затора с параметрами-допущениями | Симуляция одного отряда, запись боя по тикам |
| 3.2 | Наш Lua-ИИ запускается в симуляции через `lupa` с теми же контрактами | Одинаковый код в игре и в симуляции |
| 3.3 | Просмотрщик: препятствия, запас места, рамка строя, маршрут, точки | Любой прогон можно посмотреть глазами |

**Критерий готовности:** все случаи T0–T5 прогоняются в симуляции с наивным
приказом; видно, где по модели будет затор; допущения перечислены в одном месте.

### Этап 4. Прицельный сбор данных в игре

Только данные из таблицы этапа 2. Профиль `config/readouts/obstacles.json`:
позиция, заданная позиция, направление, ширина, движение, позиции бойцов, фаза, время.

**Критерий готовности:** допущения симуляции заменены измерениями; после
подгонки симуляция предсказывает исход (дошёл/застрял) как игра минимум в
80% случаев, время — ±25%.

### Этап 5. Алгоритм (Lua, базовый навык «идти в точку»)

| Шаг | Что делаем | Результат |
|---|---|---|
| 5.1 | Маршрут по коридорам: поиск пути по сетке, где запас места ≥ половины ширины строя + допуск; штраф за сужение и за длину | Маршрут или «пути нет» |
| 5.2 | Исполнение по точкам: на каждом участке направление по ходу пути и ширина, помещающаяся в коридор; сужение до прохода, расширение после | Цепочка приказов движения с шириной и направлением |
| 5.3 | Проверка конечной позиции: прямоугольник строя целиком на свободном месте, иначе сдвиг, поворот или сужение | Выполнимая конечная позиция |
| 5.4 | Застревание: распознать и выйти — шаг назад, сузить строй, перестроить маршрут с большим запасом, пометить место | Отряд не стоит «афк» |
| 5.5 | Журнал решений: маршрут, ширины, причины перестроения, застревания | Видно, почему отряд пошёл так |

**Критерий готовности:** модульные тесты на синтетических картах (коридор,
Г-угол, подкова, проход уже строя, пути нет); в симуляции на T0–T5 ноль застреваний.

### Этап 6. Проверка в игре

На случаях T0–T5: наивный приказ против нашего алгоритма, по 3 повтора.

## 4. Критерии приёмки задачи

Задача считается решённой, когда на случаях T0–T5 **в игре** выполняется:

| Критерий | Порог |
|---|---|
| Застревания с нашим алгоритмом | **0** |
| Доля дошедших, где путь существует | **100%** |
| Время до цели | Не хуже наивного приказа там, где наивный дошёл; конечное там, где наивный застрял |
| Точность конечной позиции | Центр ≤ 5 м от цели, направление ≤ 15° |
| Честное «пути нет» | Если прохода нет, отряд сообщает об этом, а не стоит у препятствия |
| Надёжность прогона | Нет ошибок Lua, бой завершается сам |
| Симуляция | Совпадение исхода с игрой ≥ 80%, время ±25% |

## 5. Риски

- «Свободна ли площадка» может значить не то, что «можно встать» (проверяем на этапе 1).
- Движок может проложить путь от промежуточной точки к следующей по-своему,
  снова через узкое место. Тогда нужны более частые точки.
- Мелкие объекты (отдельные деревья, заборы) могут не попасть в сетку 3 м.
  Возможно, около препятствий нужна сетка 1–2 м.
- Перестроение может быть долгим и съесть выигрыш по времени.
- Позиции отдельных бойцов ещё не проверены в игре.

## 6. Открытые вопросы

- Откуда ИИ в бою берёт карту препятствий: снимать вокруг себя во время
  расстановки (сетка 3 м снималась меньше чем за секунду) или брать заранее
  снятую? Для общего ИИ нужен первый вариант, для разработки годится второй.
- Какой отряд берём первым: копейщики Империи (120 бойцов) как проверенный вариант?
- Шаг сетки около препятствий: 3 м или мельче?
