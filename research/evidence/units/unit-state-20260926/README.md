# Общие показатели состояния: пакет операторских проверок

Три ограниченных диагностических запуска на проверенном официальном поле `chokepoint_badlands_river`, без новой соревновательной итерации. Проверены три собственных типа: Spearmen без щитов, обычные Archers, пеший General of Empire rank 1. Противники служат диагностическими мишенями; во второй/третьей пробе — Empire Knights. x20, минимум графики, Ultra. Специальные способности не применялись. Сброс лимита не использовался.

## Результат и файлы

- Общий модуль: `src/units/state.lua`, SHA256 `281d255f420bb86e605d9256e7d791ea15c6cfb4355922b4a9e822d555efcb87`.
- Проверки: `tests/test_unit_state.py`, **6 passed**. Различаются known false/0 и unknown; проверены ошибочные типы, nil, nonfinite, безопасные копии векторов, запрет подробных вражеских наблюдений, фильтрация handles угроз и перечисление ключа stat_morale.
- `handoff.json`: три запуска, 7 926 собственных снимков, первые наблюдённые переходы, сравнения числовых показателей, cleanup и ограничения.
- `basic/`, `charge/`, `charge-extended/`: каждый содержит исходные capture.lua, reader.lua (точный снимок модуля), map_probe.xml, экспорт ready.xml, manifest/hash, полные JSONL, status/cleanup, fields.json, stages.json, card-stat-keys.json, card-morale-pairs.json, summary.json.
- `natural-routing.png`: проверенный график естественных повреждений и морали лучников в последней пробе.
- `fields.json`: доступность по полям, диапазоны, первые 24 различных значения и первые 16 переходов. `stages.json` — то же по стадиям. Ограничение кратких списков не затрагивает полные сырые логи.
- Снимки текущего модуля/тестов — в `sources/`; корневой hashes.json фиксирует пакет. Окончательные общие документы публикует координатор.

## Существенные наблюдения

1. Наблюдались ходьба/бег/остановка, смена направлений/ширины, боезапас, стрельба, melee, повреждения без погибших, усталость и 240 секунд отдыха с возвращением всех трёх типов к threshold_fresh. HP во время отдыха не восстановилось. Это условия одного опыта, не универсальное время восстановления.
2. native ammo_left/starting_ammo — суммарные боеприпасы: у 90 лучников стартовое значение 1800. CCO PrimaryAmmoPercent — отдельная доля. В последовательных чтениях при стрельбе встречалась разница до 0.008333 между native-отношением и CCO; не считать все readouts атомарным снимком.
3. Для живых отрядов HealthValue/HealthMax совпадало с CCO HealthPercent в пределах 3e-8. Native unary_hitpoints и CCO HealthPercent временами различались до 0.03591; конкретная причина/задержка этим не изолирована. Нельзя незаметно считать каналы синхронными.
4. Выход с поля нельзя превращать в смерть: в basic/withdraw у генерала и копейщиков IsAlive=false, number_of_men_alive=0, HealthValue=0, но HP-доли сохранялись положительными; IsWithdrawing/is_leaving_battle=true. Примеры с временем сохранены в handoff.json. Численность также падала при уходе через край, без доказательства гибели этих бойцов.
5. В `charge-extended` лучники естественно начали routing в 59.2 с игрового времени; shattered впервые в 75.2 с. Принудительный morale_behavior_rout не применялся. У остальных двух типов такого перехода не наблюдалось; их false не доказывает невозможность бегства.
6. MoralePercent имел значения выше 1 в основной пробе и до -1.78 у лучников в длинной пробе. Не clamp в [0,1], не вероятность. Наблюдались MoraleState 1–7 в совокупности; не объявлять это исчерпывающим enum.
7. Ключ `stat_morale` найден перечислением `CcoBattleUnit.UnitDetailsContext.StatList.At(i).Key`. `Value`, `DisplayedValue`, `ValueBase` читаются численно. Это числовой readout карточки; он изменяется иначе, чем MoralePercent, и не доказывает точный текущий панический запас/порог. У лучников длинной пробы Value менялся от 50 до -72. Полные пары и состояния сохранены.
8. IsAwaitingOrderAfterRally/IsOutOfControl и другие false-only поля подтверждают тип/доступность, но не их естественные триггеры. Новые игры ради получения всех true не проводились. Damage readouts не сертифицируют MATCH-IDLE-001.

## Исправление и границы

В первом снимке три native getters `left_flank_threat/right_flank_threat/rear_threat` ошибочно ожидались как number. Сохранённые type_userdata — ошибка оболочки, **не отсутствие API**. Оба последующих запуска используют исправленный модуль: nil преобразуется в известное отсутствие (`value=""`), возвращённый unit — только в разрешённый ID после native проверки видимости; сам объект не экспортируется. Подтверждены видимые ссылки `target3` у генерала. Скрытые цели дают unknown.

Модуль требует доверенного подтверждения ownership от вызывающего адаптера. Он не аутентифицирует произвольного caller и не является sandbox. Для всех чужих отрядов выдаёт только результат native проверки видимости; подробные поля заблокированы даже при visible=true. Нет автоматического расширения API v1. Тесты/хеши старых бойцов и `src/competition/engine.lua` сохранены.

`HoldingPosition`/`ActiveBehaviours` под такими именами не найдены в просмотренных battle_unit/CcoBattleUnit материалах. Сняты документированные is_behaviour_active для defend/skirmish/fire_at_will/change_formation_spacing и StatusList.Keys; не приписывать им неподтверждённую эквивалентность. Тексты CCO могут содержать локализационные токены и цветовую разметку.

Подготовительные телепортации явно отмечены fixture_teleport. Удары/усталость/мораль после setup естественные. Различия между повторами не являются детерминированным replay или статистической оценкой баланса. Во всех трёх запусках probe_done без probe_error; собственные PID закрыты, установленные файлы удалены. Никаких скрытых боевых данных iteration-0001 в этот пакет не включено.

## Воспроизведение

Из корня проекта, при отдельно разрешённом диагностическом запуске и отсутствии пользовательской игры:

```powershell
python tmp/agents/battle-operator/unit-state-20260926/replay.py charge-extended
& tools/map-capture/launch.ps1 -TimeoutSeconds 180
```

replay.py собирает именно архивные Lua/XML bytes и требует совпадения исходного pack SHA256; сама команда игру не запускает. Для basic нужен TimeoutSeconds 400. Запуск автоматически закрывает только свой процесс. Архивные JSONL/XML не перезаписывать. Анализ нового каталога выполнить `analyze.py <новый run> <новое имя>`; источник сохраняется копией. `build_probe.py` создаёт свежую пробу с текущим модулем и поэтому не является точным воспроизведением первого ошибочного варианта basic.
