# Общие условия для аналитиков сверки (build/conform)

Проект: ИИ для сражений Total War: WARHAMMER III. Симулятор боя на PyTorch `tools/nn/sim/`, параметры
`config/nn/sim.json` (у каждого блока есть поле `why` — почему такое число), правила игры из базы
`config/nn/game_rules.json` (_kv_rules / _kv_morale / _kv_fatigue), паспорта отрядов `config/nn/units.json`,
эффекты `config/nn/effects.json`, способности `config/nn/abilities.json`. База знаний: `docs/ru/game/mechanics/*.md`
(в README.md есть таблица «расхождения с нашим симулятором»). Документацию читать только на русском (docs/ru).

Направление пользователя (06.10): сначала привести каждую механику и каждую карточку отряда симулятора к
формулам и числам игры; только потом сверять бои. Цель общей работы — ГЛАВНАЯ ТАБЛИЦА СООТВЕТСТВИЯ.

УЖЕ СДЕЛАНО (сначала прочитать, не повторять, а дополнять и проверять):
- `build/web_mech/formulas.md` — поиск формул в сети (39 ссылок);
- `build/web_mech_sol/audit.md`, `build/web_mech_opus/audit.md` — аудиты формул;
- `build/prespec/batch2.md` — их слияние, 23 пункта (часть уже сделана: смотри текущий код и sim.json).
НЕ ИССЛЕДОВАТЬ: шанс попадания в рукопашной (им занят аналитик, `build/hitchance`) и точность стрельбы
(аналитик, `build/accuracy`) — не трогать.

ИНТЕРНЕТ ОБЯЗАТЕЛЕН (пользователь настаивает): формулы и тесты сообщества TWW2/TWW3 — гайды Steam, тесты на
reddit (r/totalwar, r/totalwarhammer), twwstats.com, заметки моддеров (SFO, Radious), блоги и патчноуты CA
(Feature Focus), вики. Fandom отдавал 402, TWCenter 403 — брать сниппеты поиска, зеркала, кэш, github.
Каждая строка — с источником: URL или ключ базы (таблица.ключ). Нет источника — так и написать «не найдено».

ФОРМАТ строк (markdown-таблица, по-русски, простым языком, коротко):
| ID | Механика / параметр | Правило игры (формула + числа) | Источник (URL / ключ базы) | У нас (файл:строка, ключ sim.json = значение) | Статус | Влияние на бои | Что сделать (и какие подогнанные параметры убрать вместе) |
Статус — ровно одно из: MATCHES (симулятор делает как игра, с числами игры) / FITTED (параметр подогнан под
записи и подменяет или прикрывает правило игры — написать, что именно прикрывает) / DIFFERS (правило есть, но
формула или число другие) / MISSING (правила игры в симуляторе нет). Если механика в игре есть, но в наших боях
(Империя против скавенов, только пехота, лорды пешие, лучники, пращники, ополчение с мушкетами) не встречается —
статус MISSING и влияние «нет в наших боях».
Влияние: высокое / среднее / низкое / нет + одна фраза почему.
После таблицы — список ТЕСТОВ на уровне формулы (один отряд/пара, без сверки боёв), которые проверяют правило
напрямую: что задать, что должно получиться (число).

ПРАВИЛА:
- Только анализ: tracked-файлы не менять. Все свои файлы (скрипты, json, md) — только в `build/conform/`.
- Python на хосте: `.venv/Scripts/python` (без torch). База игры читается только `py -3.14` (нужен
  compression.zstd). НЕ запускать `py -3.14 -m tools.nn.gamedb` и `py -3.14 -m tools.nn.units` без `--out` —
  они ПЕРЕЗАПИСЫВАЮТ tracked config. Можно: `py -3.14 -m tools.nn.units --out build/conform/<имя>.json`, или свой
  скрипт в build/conform/, который импортирует `tools.nn.dbtables.read_tables` / `tools.nn.gamedb.read_entries`
  и пишет в build/conform/. Путь к игре: `tools.config.load()["game_dir"]` + `/data/db.pack`.
- Контейнер Docker не нужен, не запускать. Видеокарту не трогать. Файл `build/gpu-train.lock` не трогать.
- Ожидание только `bash tools/ops/wait.sh -t СЕКУНДЫ ФАЙЛ REGEX`. Без команд, требующих ручного разрешения;
  без rm -rf, git reset, git clean. Не коммитить.
- Время: около 60–70 минут. Лучше полный охват с пометкой «не найдено», чем глубина в одном месте.
- Последнее сообщение — короткий отчёт (до 200 слов): что в файле, счёт строк по статусам, что не нашлось.
