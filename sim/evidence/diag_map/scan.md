# Снимок карты: как снимается, слой «нельзя встать» (31.10)

## Как снималось раньше
- Цель сборки `map-capture` (`src/entries/map_capture.lua`, `src/apps/map/adapter.lua`, сценарий `scenarios/map_capture.xml`:
  крылатые уланы + коссары на Кислеве, catchment_04). На паузе в фазе расстановки по каждому узлу сетки:
  `bm:get_terrain_height(x, z)`, `bm:is_area_clear(p, 0, step, step)` (квадрат шаг × шаг), `bm:ground_type(p)`.
- Сетка: узлы, кратные шагу (`--nodes`), шаг 1 м, 1025 × 1025 = 1 050 625 узлов на рамку радара ±512 м.
- Перевод: `python -m tools.nn.map_grid convert` → `heights.npz` (height, clear, ground), `meta.json`, `preview.png`.
  Снимок 28.10: высоты 14,5 с по часам Lua.
- Уже был режим `--features` (с сентября, для Катая): после расстановки x20 и паузы — список объектов `bm:buildings()`, CCO
  и `unit:can_reach_position` по каждому узлу для первого отряда каждой стороны. Для полной карты 1 м не запускался.

## Что игра даёт скрипту про проходимость (документация Lua WH3, chadvandy; проверено в игре)
- `bm:is_area_clear(pos, bearing, w, d, is_naval)` — «свободна ли область от ограничений поиска пути»; один boolean, без причины.
- `unit:can_reach_position(pos)` — может ли отряд дойти до точки; только в фазе Deployed (в расстановке ответы другие).
- `bm:ground_type(pos)` — тип земли (`shallow_water`, `deep_water`, `forest`, `rock`, …). Глубины воды, уровня воды,
  функций `is_in_water` / `is_position_valid` в API нет.
- `bm:buildings()` — объекты (валуны, скалы, заборы, дома): положение и название, без контура.
- Отряд: `ordered_position()` — по нему видно, принят ли приказ.

## Что сделано
- Lua снимка не менялся: режим `--features` уже даёт всё нужное, на полной карте 1 м он отработал без правок.
  `src/entries/move_probe.lua` (проба движения): `plan.units` — несколько своих отрядов, `leg.unit` — кто идёт; в каждом
  замере `is_hidden`.
- `tools/nn/map_grid.py`: `capture` теперь всегда с `--features`; `parse_reach`, `passable_layers`, `write_layers`,
  `preview_layers`; команда `layers <run> --name <карта>` (только новый слой для уже снятой карты, проверяет, что
  сетка, высоты и clear совпадают; `heights.npz` не трогает). Тесты: `tests/tools/test_map_grid.py` (+3).
- Правило: `blocked = 1`, если узел недоступен обоим отрядам; где доступность не читалась — `is_area_clear = нет`.
- Файлы: `build/maps/<карта>/passable.npz` (blocked uint8 [iz, ix], x0, z0, step), `passable.png`, `meta.json` →
  `passable` (+ сколько узлов каждого типа земли закрыто; остальное без изменений).
- **Вода и лес отдельными слоями не снимаются.** Сделанные было `water.npz` (мелкая / глубокая) и `forest.npz` на обеих
  картах совпали бит в бит с классами 2 / 3 / 1 слоя земли симулятора (`ground.py` GROUND_CLASS по `heights.npz` ground) —
  повтор, убраны. Проба в игре подтвердила, что «в лесу» у игры = тип земли `forest` (ниже).

## Предложение для следующего кодера (не сделано)
- Симулятор: при загрузке карты читать `passable.npz` (тот же x0, z0, шаг). Приказ в точку «нельзя» — отвергнуть
  (отряд стоит), как в игре; бойцов не пускать в узлы «нельзя» (выталкивать к ближайшему свободному, как стволы).
  `realmap` — выбирать места старта по `blocked` вместо `clear` (на речной карте старт сейчас попадает на мелководье
  в крыльях, где игра стоять не даёт). Вода и лес — уже есть (классы земли `ground.py`).
- Сеть: в окно карты добавить долю «нельзя встать» на клетку; в мосте — тот же файл (снимается один раз на карту,
  вход один в один).
