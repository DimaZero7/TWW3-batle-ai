# Новые отряды: полный список свойств и способностей против симулятора

Дополняет `plan.md` (паспорта, часть механик) и пробы `newunits_game.json` (коммит `bd0ad4e`) — здесь не
повторяется то, что там уже измерено, только база игры (`unit_attributes_to_groups_junctions`,
`land_units_to_unit_abilites_junctions`, `melee_weapons`, `projectiles`), интернет (где база неясна) и
сверка с `tools/nn/sim` / мостом / `ai_like`. Источник атрибутов и способностей — паспорт
(`build/newunits/passports.json`, тот же код, что у `config/nn/units.json`); источник расшифровки
способностей — `build/newunits/abilities_new.json` (`py -3.14 -m tools.nn.abilities`). Магический флаг
(`f13`) проверен отдельно прямым чтением `melee_weapons` из `db.pack` (см. ниже) — таблица в `plan.md`
потеряла одну ячейку при наборе, здесь числа даны напрямую из базы, без восстановления по смещению.

Метод: 1) паспорт (атрибуты/способности по ключу) → 2) `abilities_new.json` (что делает каждая
способность: числа, условие, длительность/перезарядка) → 3) интернет (fandom через выдержки поиска —
сами страницы fandom/honga закрыты, 402/403, как и в прежнем заходе) → 4) `config/nn/effects.json` /
`config/nn/abilities.json` / `config/nn/units.json` (что уже заведено) → 5) важность для ровной карты без
конницы и артиллерии.

## Итог по активным способностям (сквозной вопрос задания)

**Ни у одного из 6 отрядов нет ни одной активной (с перезарядкой, по решению игрока/ИИ) способности.**
Все найденные ключи способностей — `wh2_main_unit_passive_scurry_away`, `wh2_main_unit_passive_strength_in_numbers`,
`wh_main_unit_passive_frenzy` — в `config/nn/abilities.json` и `build/newunits/abilities_new.json` помечены
`"passive": true, "active_s": -1, "recharge_s": -1`: включаются/выключаются сами по условию
(мораль, здоровье), игрок или ИИ их не выбирают. Алебардисты — вообще без единой способности
(`"abilities": []` в паспорте). Для сравнения: все способности с `active_s > 0` в том же файле
(`wh_main_character_abilities_rally`, `..._stand_your_ground`, `..._deadly_onslaught`, `..._foe_seeker`,
`wh2_main_character_abilities_verminous_valour`, `wh_main_lord_passive_hold_the_line`) — исключительно
лордовские (`character_abilities` / `lord_passive` в ключе). Проверено отдельным агентом по коду (`tools/nn/sim/abilities.py`, `tools/nn/model/{abilities,observation,heads,decide}.py`,
`tools/nn/companion/exchange.py`, `src/apps/bridge/adapter.lua`): это **не архитектурное ограничение, а
только данные**. Ни сеть, ни мост, ни Lua не проверяют касту/«лорд» где-либо на пути применения
способности (`tools/nn/sim/abilities.py:180` гейтит только по `self_cast`; `src/apps/bridge/adapter.lua`
`use_ability` зовёт `perform_special_ability` на любой именованный отряд). Единственная причина, почему
способности есть только у лордов, — в `config/nn/abilities.json` у лордовских ключей `self_cast: true,
passive: false`, у всех остальных (в том числе у наших трёх) `passive: true`. Завести активную
способность любому отряду сегодня — **не новый код, а один паспорт** с нужными флагами; подробности —
раздел «Мост и ИИ» ниже.

## Чего нет ни у одного из 6 отрядов (явная проверка примеров из задания)

Прямо по паспорту (`attributes`/`abilities`, `build/newunits/passports.json`) — у наших 6 отрядов **нет**:
расходного материала (`expendable`), неустрашимости (`unbreakable`), скрытности сверх леса (`stalk`,
«снайпер», «незаметный»), стрельбы на ходу (`mounted_fire_move` — у Пушки её нет, она стреляет только стоя),
огня сквозь своих (снаряд `low` — настильный, нужна чистая линия, не навесной), уязвимостей
(`damage_resist.flame`/`magic`/`missile` у всех 0, не отрицательные), отвращения/ненависти к типу врага,
страха, ужаса, регенерации, лечения, барьера. Всё это — проверенное отсутствие, а не «не посмотрели».

## Мост и ИИ (сквозной вопрос — проверено по коду)

**Эффекты удара (яд / «Заражение» / подавление): дырка сквозная, от базы до сети.** Поле `contact_phase`
уже читается из `melee_weapons` (`tools/nn/dbtables.py:67`), но дальше никуда не идёт: не в
`tools/nn/units.py`, не в `config/nn/units.json`, не в каталоге эффектов `tools/nn/effects.py`. Временного
«эффект от удара, держится N с, обновляется, один за раз» механизма в `tools/nn/sim` нет вообще: два
существующих похожих механизма не подходят — таймеры-слоты в `tools/nn/sim/effects.py` (`TIMERS=2`,
строки 50, 226–260) срабатывают от **своего** состояния, не от удара по себе; `snap_s`/`snap_ab` в
`tools/nn/sim/abilities.py` (150–151, 195–233) кладут эффект на **своих** в радиусе при применении
способности, а не на поражённого врага. `melee.py:strikes()` (131–184) и `missile.py:volley()` (571–629)
уже считают нужные тензоры попаданий `[B,N,N]`, но результат никуда не привязывается, кроме урона.
**Оценка:** ~6–8 файлов, 12–20 часов — поле из базы дать до паспорта, новый вид эффекта в каталоге,
новое состояние в `tools/nn/sim/state.py`, зацепка в двух местах (`melee.py`, `missile.py`), выход в
сеть (`observation.py`), тесты. Схему базы разбирать не нужно — имена полей уже известны.

**Пушка: 18 пуль за залп не читается.** `tools/nn/sim/missile.py:581–582` — `per_man = dt /
u["reload"].clamp(...); shots = u["men"] * per_man`: один снаряд на бойца за долю цикла перезарядки,
`shots_per_volley` нигде не умножается (ноль упоминаний в `tools/nn/sim` и `tools/nn/model`; есть только
в паспорте/экстракторе — `tools/nn/units.py`, `data/units/probe-units.json`, уже 18 у Пушки). Правка —
в этих двух строках (и, возможно, в расчёте перезарядки `params.py` около строк 104–111).

**Крысоволки: опечатка касты, упадут в «прочее».** `tools/nn/model/passport.py:16–17` — `CASTES` содержит
строку `"warbeast"` (без подчёркивания), а каста в базе и в паспорте — `"war_beast"`. Сравнение строгое
(`_hot()`, строки 35–36), так что оба отряда крысоволков тихо попадут в отряд «прочее» вместо своей
касты. **Нужно поправить до ввода отряда** — иначе сеть не отличит их от случайного «не распознанного»
юнита по касте. Размер/«большой»: `params.py:134` — `"large": u.get("size","small") != "small"`; прямая
проверка `config/nn/units.json` показывает, что сегодня у всех отрядов `size` = `small` (касты в
паспортах — только `lord`, `missile_infantry`, `melee_infantry`), так что бонус против больших и защита
от натиска больших не сработают ни у кого, включая крысоволков, пока в ростере нет ни одной цели класса
`large`.

**Шаблон строя — без вайтлиста.** `tools/nn/units.py:179` берёт шаблон `unit_spacings` обычным поиском по
ключу из полного дампа базы; `params.py` (74–80) читает только числа `h`/`v`, уже посчитанные в
`units.json`, имя шаблона ему не важно. Новые шаблоны (`wh_main_infantry_rabble`, `wh2_main_skv_weaponteam`,
`wh_main_war_beasts`) пройдут без правок. Мелочь: поля `chaotic`/`scatter` паспорта `tools/nn/sim` вообще
не читает (только экстрактор) — не используются, но и не мешают.

**Роль ИИ (`ai_usage_group`) — поле не заведено вообще, ни у кого.** Это касается не только крысоволков:
поиск `ai_usage_group` по всему репозиторию находит только сырую схему базы (`tools/nn/dbtables.py:43`) и
описания в документации — ни в `passport.py`, ни в `config/nn/units.json`, ни в `tools/nn/train/opponents.py`
или `behaviour.py` этого поля нет. То есть у Пушки (`ranged_direct`) и у Алебардистов (`melee_anti_large`)
«правила уже есть» не потому, что учтена их роль из базы, а потому, что их поведение задают **другие**,
уже заведённые поля (каста `missile_infantry`/`melee_infantry`, `can_skirmish`) — ровно как у всех
нынешних отрядов той же касты. Для крысоволков (`melee_flanker`) это не так: существующий «фланговый»
код в `opponents.py` (строки 507–525, `flank_m`; план атак `pincer.py`/`direct_fire.py`/`reserve.py`) —
жёстко заданная геометрия для конкретных учений, не правило по полю паспорта. Значит, обход с фланга для
крысоволков в `ai_like` — **новая работа** (не правка существующего правила), и привязывать её к полю
`ai_usage_group`, раз оно всё равно не читается ни для одного отряда, смысла нет — проще по касте
(`war_beast`, после исправления опечатки) или по ключу отряда.

**Активная способность у любого отряда (не только лорда) — архитектурно уже можно.** Ни в
`tools/nn/sim/abilities.py` (гейт по `self_cast`, не по касте), ни в `tools/nn/model/{observation,heads}.py`
(гейт «свой, самоприменяемая, готова, принимает приказы»), ни в `tools/nn/companion/exchange.py` (фильтр
только по стороне), ни в `src/apps/bridge/adapter.lua` (`use_ability` берёт любой именованный отряд) нет
проверки на лорда/касту; «лорд» фигурирует только в комментариях и примерах. Единственный гейт — данные:
`tools/nn/model/abilities.py:128` `usable[i,k] = self_cast and not passive` — у всех трёх способностей
наших 6 отрядов `passive: true`, поэтому `usable` всегда false, как и у любого другого обычного отряда
сейчас. Если бы у одного из новых отрядов была настоящая активная способность, её включение не стоило
бы новых файлов — только паспорт с `self_cast: true, passive: false` (готовый конвейер — сеть
(`model/abilities.py` → `observation.py` → `heads.py` → `decide.py` → `chain.py:162`) → симулятор
(`sim/abilities.py`) → мост (`companion/exchange.py`/`loop.py`/`script.py`) → Lua
(`bridge/services.lua` → `bridge/adapter.lua` → `orders/adapter.lua`), те же ~10–12 файлов, что у
лордов, но без изменений в них). Для наших 6 отрядов это не требуется: ни одной активной способности
у них в базе нет.
