# Приказ «лицом» в рукопашной: выход из боя, поворот строя (статический разбор, 27.10.2026)

Только файл игры на диске (`Warhammer3.exe`, открытый код `.udata`), база (`_kv_rules`). Игра не запускалась,
отладчика не было, защищённые секции не трогал; пропусков из-за защиты нет. Проект Ghidra `notes/melee_turn/gproj`
(копия `melee_flee/gproj`), `notes/melee_turn/dec.sh`, скрипты `notes/melee_turn/scripts` (копии из melee_flee),
индекс смещений `notes/melee_turn/idx_battle.pkl`. Сырые выводы `notes/melee_turn/d1.c … d15.c`.
Уверенность: **В** — прочитано целиком; **С** — прочитано, смысл поля по контексту; **Н** — догадка.
Тик боя 100 мс. Проба в игре: `TWW3-batle-ai/build/diag_g49/turn_melee/` (запуск `build/charge-probe/runs/20261027-211211`).

## 0. Сообщество
Правила нет. Игроки: «после перестроения/бегства врага отряды стоят без дела, нужен новый приказ атаки», «отряд бьёт в
ответ, только если обновить приказ» — без чисел. Ключи `melee_breakoff_*` в сети не объяснены (twcenter: тред
«kv_rules tables» перечисляет ключи, но объясняет только упор). Ничего про «задняя шеренга становится передней».

## 2. Выход из боя по новому приказу — В

### 2.1 Список «враги рядом» (отряд +0x3208)
Запись 0x18 байт: `{отряд врага*, состояние int +8, таймер int +0xc, «видел в этот тик» +0x10, «есть касания» +0x11,
«враг перед строем» +0x12}`. Каждый тик (`143048b4c`):
- все таймеры записей и таймер отряда +0x3254 уменьшаются на 1 (если > 0);
- `14304bbd4` проходит всех врагов, чей строй ближе `свой радиус + 100 м + радиус врага` (`14301028c`): новый — новая
  запись (`14300c3b8`: таймер 0, состояние 1, потом пересчёт), старый — пересчёт (`14301f130`); не попавшие в радиус
  записи удаляются. Порог «вступил» N = max(1, бойцов × k): k = `melee_attack_threshold_modifier_ordered` (1,0) при
  приказе, `…_idle_default` / `…_idle_ammo_remaining` / `…_artillery` (все 1,0) без приказа; 0,15 — если у врага особый
  флаг (`142e53a94`, Н: одиночка?), ×0,5 — `143033afc` (Н), 0 — бегущий/уходящий враг.

### 2.2 Новый приказ (`1430472a8`)
```
если у отряда есть приказ (+0x2f88 ≠ 0) и флаг «приказ новый» (+0x2f94):
    ...
    если слот приказа vfunc 0x108() → 1430168d4(список +0x3208, цель приказа = vfunc 0x68())
1430168d4(список, цель):
    отряд +0x3254 = round(10 с × 10 тиков) = 100              (1430423f4, melee_breakoff_total_immunity_secs 10)
    для каждой записи врага:
        если враг == цель приказа:      таймер = 0
        иначе если 1430268e0(свой, враг) («есть касания»): таймер = round(24 × 10) = 240, пересчёт состояния
```
- Какие приказы дают vfunc 0x108 = «да», в коде не нашёл (классы приказов лежат в очереди из 40 слотов по 0x120 байт
  +0x2a0, индекс текущего +0x2f8c; таблицы классов не опознал). По пробам: движение (в т. ч. на своё место — «лицом»),
  отход, атака другого отряда — да; «стоп» — нет (`holdmelee`: стоп не закрывает и не начинает окно); повтор атаки на
  того же — да, но цель получает таймер 0 (бьёт как прежде, проба `fresh`).
- Lua `goto_location_angle_width` (`142ee7820`): угол × 182,04 (65536/360), ширина > 0, бег; строит ту же команду
  движения, что игрок (`142ea9c88`, таблица `143ab9b00`), и шлёт в очередь команд. Значит «лицом на месте» — обычный
  приказ движения с точкой = своё место.

### 2.3 Состояние записи (`1430213a0`)
```
цель = (у отряда есть приказ с целью-отрядом и это этот враг)
если (отряд +0x3254 == 0  или  цель):
    если враг не годен в противники (143034fe4: не враг / нельзя бить) или (бегущий при флаге отряда +0x3d1c бит 0
         и не цель): состояние 0; конец
    если таймер записи == 0:
        n = число касаний (14303cac8);   N — порог из 2.1
        n == 0 и не цель                  → 4
        n < N/2:  враг «перед строем» (1430e0780) → 3, иначе 4
        n ≥ N/2:  (+0x3b70 == 0 или n ≥ N) → 1, иначе 3
        конец
состояние 5   (выход: таймер идёт, или первые 10 с после приказа и враг не цель)
```

### 2.4 Что делает состояние 5 (`143016954`, `14305b300`) — В
`14305b300(боец, враг-боец)` = «не бить»: 1, если у бойца свой таймер +0xa34 > 0 (`break_off_ignore_collision_time`
= 0, не ставится), или отряд врага в списке своего отряда в состоянии 5 (при `break_off_speed_and_direction_checks` = 0
проверка направления и скорости пропускается), (и ещё одна ветка — по бойцу врага vfunc 0x2f0 и полям бойца +0x5c0 /
+0x4c8, смысл не выяснил, Н). Вызов стоит во всех путях начала удара: ответный удар `143074dcc` (`!= 1` → бить),
удар по касанию `143056730` (`== 0` → бить), `14306bc78`, `1430898ec`, свободный бой `14308b938`, подход `14308b608`,
удар по прибытии `14308f0e0`, парные схватки `142f86cb8`, `142f88074`, `142f8d324`.
Итого: **свой отряд не начинает ни одного удара (и парных схваток) по врагам в состоянии 5**. Враг бьёт как прежде:
у него в своём списке наш отряд не в выходе. Уже начатый замах доигрывается (в пробе удары до 0,9–1,8 с после приказа).

### 2.5 Сроки
- По каждому врагу, который **касался** отряда в момент приказа: 24 с от приказа (240 тиков), даже если касание
  прервалось и возобновилось (запись живёт, пока враг в 100 м).
- По любому врагу, кроме цели приказа: первые 10 с после приказа (новые касания тоже).
- Новый приказ того же рода перезапускает оба таймера; приказ атаки на этого врага обнуляет его таймер сразу.

## 3. Защита, атака, мораль во время выхода — В/С
- Шанс и урон (`melee_module.md` 2.1–2.2) не смотрят ни на состояние записи, ни на приказ. Сторона удара — по взгляду
  каждого бойца-защитника на каждый удар (`1430a6380`): повернувшийся боец получает удары во фланг (защита × 0,6) или в
  тыл (× 0,3). Бонус строя +5 (`melee_defence_formed_attack_bonus`) — по биту 1 поля отряда +0x3d1c; записей в это поле
  в коде боя нет (только чтение, 72 места) — приказ его не меняет (С).
- Мораль: сторона каждого врага в касании записывается при первом касании и держится, пока он в касании
  (`morale_module.md` 2.6, `14302682c`) — поворот строя новых −6/−14 за фланг/тыл от уже касающихся не даёт (С: по
  прошлому разбору). Отдельного эффекта «перестроение/выход» в морали нет.
- Ключей «штраф за перестроение» в `_kv_rules` нет.

## 4. Поворот строя
Код машины приказа движения (состояния `BUILD_REFORM_SPINE`, `FIND_FINAL_TURN_SPINE_FORMED_MOVE`, `PAUSE_BEFORE_TURN`,
`TURN_ENTITIES_TO_FACE`, `MOVE_TO_SLOT`, `MOVE_FORMED`) нашёл по именам, но правило «повернуться кругом на месте или
перестроиться» и скорость не дочитал: функции состояний — переходники через таблицы, много уровней. Что видно:
- `PAUSE_BEFORE_TURN` вход (`1432748a4`): угол от центра отряда к точке цели, каждому бойцу приказ «смотреть» с этим
  углом (vfunc бойца 0x398, флаги 0x81); выход (`1432764d8`) — по `1430cd2a8` (готовность, Н). Это состояние приказа
  атаки/стрельбы (владелец по −0x30, как CHASE), не движения (С).
- `MOVE_TO_SLOT` (`143275d90`) ждёт, пока ни у одного бойца группы нет действия +0x898 (Н: начатого удара/схватки).
- Строй стоящего отряда (`143286cd0`): раз в 1 с бойцы дальше `r + 1,5 м` от своего места идут на место; место i —
  боец i (melee_stacking 2.1).
Правило поворота — по пробе (раздел 5), не по коду (Н для «почему»).

| свои потери 0–30 с / контроль | 1,26 | 1,56 | 1,26 | 1,26 | 1 |

- Ни одного удара с 1,8 по 24,9 с во всех 4 дорожках — ровно окно 24 с + первый замах. Отряд всё это время «в
  рукопашной» и без цели (has_target 0); враг бьёт его как прежде. Сходится с 2.4–2.5.
- 180°: бойцы остаются на своих местах и поворачиваются (корреляция −0,8): **задняя шеренга становится передней**, бывшая
  первая — спиной к врагу. 90°: бойцы идут на новые места (глубина вдвое, корреляция 0,2), ось строя переламывается за
  6–8 с. Свободно (без врага, `movement.md`): 90° за 5–6 с, 180° за 4,8 с — в бою 90° вдвое медленнее, 180° — у копейщиков
  так же, у двуручников вдвое (почему — Н: доигрывание замахов/парных схваток, тела врагов, отбрасывания).
