# Снаряды в полёте: где игра их держит (31.10.2026, для memreader-проб)

Статический разбор Warhammer3.exe (15.10.2026, sha256 9bd58c63…e496). Декомпиляция: `notes/mem/m1.c`, `m2.c`;
`notes/dec27.c` (1430a3ee0), `notes/trees/t7.c` (1430bb044).

## Цепочка
- `142dda860` — обновление мира боя (world = `*(entity+8)+0x440`): по очереди зовёт подсистемы
  `[world+0x178]` → `1430b9f28`, `[world+0x1c8]` → **`1430ba7a8`** (менеджер снарядов), `[world+0x150]`, …
- **`1430ba7a8(mgr)`** — раз в такт симуляции:
  1. пачки (`+0x58` вектор, данные `+0x60`, размер `+0x5c`): готовые (`1430ade10`) — в свободный список `+0x78`;
  2. **активные снаряды — вектор `mgr+0x10`** {cap u32 +0x10, size u32 +0x14, data* +0x18}: с конца, у кого
     `+0xc0 == 7` — освобождается (`14309cc20`, в свободный список `+0x40`, на место — последний);
  3. каждому активному — `1430ba364(p)` (→ `1430bea34`, `1430bb044` шаг полёта, `1430be74c`, `1430c05e4`); у кого
     состояние 5 или 6 (лежит) — счёт; лежащих > 1000 — лишним ставит 7;
  4. пачкам — `1430ba428`;
  5. новые снаряды (`mgr+0x20` вектор: size +0x24, data +0x28) дописываются в активные (`14132c544`), то же для пачек.
- Сигнатура начала `1430ba7a8` (33 байта, 1 совпадение в файле): в `build/mem/sites.json` проекта (вне git).

## Проверено в игре (31.10–01.11, memreader 0.15.1, 5 боёв пробы dist 2)
- `1430ba7a8` идёт в потоке симуляции: hook ставится, 2213 вызовов за бой — все `other_thread_calls`, Lua-обработчик
  не вызывается. Читать список — опросом из потока скрипта.
- Глобал `144480d10` (11 мест: `[g]+0x440`): в бою `[g]` не 0, но `[g]+0x440` = 0 — это не бой.
- Обёртка скрипта `ammo_left` = `142ebe480(self, ctx)`: боец-отряд = `[self+8]`, боезапас int `+0x3d90` (40/40 = скрипт).
  `hook_next` из обработчика → ошибка Lua обёртки («bad argument #1 to 'hook_next' (expecting zero arguments)»):
  только `patcher:prefix`.
- Отряд `+0x30` (и `+0x38`, `+0x1e8`, …) → бой B: `[B+0x440]` = мир W, `[W+8]` = B, `[W+0x1c8]` = менеджер.
- Состояния объекта: 0 — выпущен (время полёта 0) → 7; на месте падения — НОВЫЙ объект в 6 (~20 с) → 7; попавший в
  бойца — новый объект 2 → 3 → 7 (стрелок сохранён). Записи базы: категория 5 (пуля ополченцев), 1 (лучники), 2 (камни,
  звёзды/стрелы ночных бегунов).

## Во что попал снаряд (01.11.2026, проба memshot, 3 боя)
- Объект «в теле» (первое состояние 2): указатель на стрелка +0x20 (как у летящего), на тело, в которое попал, **+0x40**,
  ещё одна ссылка на то же тело (или соседа) +0x198 (найдено сверкой полей объекта 0…0x200 с адресами бойцов, 200
  объектов; `apps.mem.hits`). Бывает не у каждого попадания (141 объект на 278 потерь здоровья у копейщиков).
- Вектор тел отряда артиллерии (+0x180) — 4 орудия (здоровье 540 / 543 в поле hp бойца), не расчёт; расчёт — тела с
  `m_unit` = этот отряд (здоровье 48 / 51), их указатели видны только из объектов «в теле».
- Стрела, остановленная стволом: летящий объект исчезает в воздухе внутри цилиндра ствола (trees.npz r), без нового
  объекта «лежит».
