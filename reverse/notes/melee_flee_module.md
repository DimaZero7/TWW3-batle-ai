## 2. Шанс попасть, направление, бегущая цель

### 2.1 Формула (`142e58560`, `142e32a04`, `142e73c54`) — В
Как в `melee_module.md` 2.1, по шагам:
```
A = атака + натиск·k [если атакующий «бьёт натиском» (2.4)] + бонус против пехоты/конницы/больших
D = защита [+5 melee_defence_formed_attack_bonus, если у отряда защитника бит 1 поля +0x3d1c — по всей видимости,
    включённый «строевой бой» (С)]
D = округл(D × m_напр)            m_напр: 1 спереди, 0,6 с фланга, 0,3 с тыла
D = округл(D × 1,0)               melee_outnumbered_defence_penalty (=1, ничего не меняет)
D += защита щита (в 60° от взгляда; у всех щитов 0)
ш = clamp(округл(max(0, 35 + 1,0 × (A − D))), 8, 90);  P = (ш − 1)/100
```
Округление — половина от нуля (защита 45 с тыла: 13,5 → 14).

### 2.2 Направление (`1430a6380`, `14309b698`, `142e53208`) — В
- Считается **на каждый удар, по бойцам**: вектор «защитник → атакующий» против **взгляда защитника** (его поворот,
  слот 0xc8). Сектора по 90°: спереди |угол| ≤ 45°, бок 45–135°, тыл — в 45° от спины (cos² ≥ 0,5).
- Множитель включается, только если **защитник в передней полуплоскости атакующего** (скалярное произведение
  взгляда атакующего на направление к защитнику ≥ 0, бит 3 обстоятельств). Атакующий спиной к цели штрафа не даёт.
- Отключается **только** атрибутом `flanking_immune` (0x3a) у отряда защитника (слот 0x98 → `14146ff40(…, 0x3a)`).
- **Одиночки (лорды, герои, монстры) — точно так же**: та же функция для любого бойца, отдельной ветки для
  одиночных моделей нет. У наших лордов `flanking_immune` нет (атрибуты: encourages, hide_forest).
- Сторона, с которой подошёл отряд, значения не имеет — важно, где стоит **конкретный боец** относительно взгляда
  конкретного защитника. Для лорда в кольце 4–5 врагов это одно и то же при любом числе отрядов (согласуется с зондом
  «лорд в окружении»: «сторона не важна» — сторона подхода отряда, а не место бойца).

### 2.3 Бегущий защитник — В (код), С (поворот)
- **Отдельной ветки для бегущих в шансе нет**: защита не обнуляется, множителя «бегущий» нет. Защита бегущего — его
  обычная защита (× усталость × грунт), направление — геометрия по 2.2. Бегущий бежит прочь, его взгляд — по ходу
  (С: обновление взгляда при беге не разбирал), догоняющий сзади → сектор «тыл» → D × 0,3.
- Бегущий **не начинает атак**: проверка `1430348f0` стоит в ответном ударе (`143074dcc`), атаке по событию
  (`143056730`) и атаке по касанию (`1430898ec`) — при бегстве выход. Поворота к атакующему в этих путях нет.
- Обычная парная схватка требует, чтобы оба смотрели друг на друга (90°/90°, `14308249c`) — с бегущим спиной её нет:
  удары по бегущему — свободные размахи.

### 2.4 Натиск в погоне (`1430b19a0`, `1430a9bb4`, `1430a5090`) — В (формула), С (что именно включает флаг)
```
«бьёт натиском» = f_натиска > 0  ИЛИ  «преследует»
«преследует»    = базовое (нижнее) поведение в стеке поведения отряда — «погоня» (слот 0x90 = true)
                  И цель отряда (приказ или авто-цель, 143020c84) бежит (1430348f0)
натиск при «преследует» = (целое)(стат натиска отряда × pursuit_charge_bonus_modifier 1,0)
                          — без спада 13 с, без усталости, без множителя армии, без «Сокрушительного обхода»
иначе натиск = округл(стат × усталость × f) …  (как раньше)
```
- Натиск идёт и в атаку (шанс), и в урон (делится по доле бронебойного, `142e589a4`), на **каждом** ударе **каждого**
  бойца этого отряда, пока цель отряда бежит, — по кому бы ни пришёлся удар.
- «Погоня» — поведение с таблицей `14391a690`: его обновление (`143280144`) = следовать за бегущим (`143289d50`) +
  назначать удары натиском (`1432839d0`); его создаёт функция состояния CHASE_STATE (`143274614`) машины приказа атаки;
  вход в CHASE — цель стала бегущей (`143034fe4`). Связь «нижняя запись стека +0x848 = этот объект» — по совпадению
  слота и состояний (С): запись кладётся через стек с другим базовым смещением (+0x818/+0x898, разница 0x30).
- Защита от натиска (упор, ±45°) у бегущего не срабатывает (он не в упоре).

### 2.5 Пример: лорд по бегущему лорду
Военачальник (атака 50, натиск 35, урон 280 + 120 бронебойного, интервал 4 с) бьёт бегущего Генерала (защита 45,
броня 85):
```
стоя, в лоб:   ш = 35 + 50 − 45 = 40  → P 0,39; удар 280 × (1 − 0,6375) + 120 = 221,5   → 21,6 HP/с (1 удар / 4 с)
в погоне:      D = округл(45 × 0,3) = 14;  A = 50 + 35 = 85;  ш = 106 → 90 → P 0,89
               удар: (280 + 35 × 0,7) × 0,3625 + (120 + 35 × 0,3) = 110,4 + 130,5 = 240,9
               → 0,89 × 240,9 / 4 = 53,6 HP/с
```
Наоборот (Генерал: 55 / 40 / 290 + 140 по бегущему Военачальнику: защита 55 → 17, броня 90): ш 90, удар 256 →
**57,0 HP/с**. Замер проекта 52,8 HP/с ≈ 53,6 — один удар в 4 с, все с P 0,89 (без парных схваток и прерываний).
Стоя в игре 14,8 против 21,6 по формуле — разница, по всей видимости, парные схватки, прерывания и повороты, которых в
погоне нет (С).

## 3. Темп ударов по бегущему — В (код), С (смысл полей)
- Интервал общий: действие атаки (`14325fca4` и соседние) каждый тик ждёт `14305ec7c` (сейчас − отметка ≥ интервал
  оружия). Это же действие запускает и задача натиска по прибытии (`14308f0e0` → `143081f18`: цель в досягаемости и в
  ±15° от взгляда), так что **удар «с ходу» интервал не обходит**. Отдельных «догоняющих» ударов, множителя урона
  по бегущим или укороченного интервала нет.
- Погоня (`1432839d0`, `charge_module.md` 2.4): строй ближе 8 м к строю бегущих → каждому свободному бойцу (не в парной
  схватке и не в задаче атаки, `14326c55c`) ближайший бегущий; если до него < max(4 м, 5 с × (скорость натиска
  преследователя (+0x30 записи) − скорость бегущего (+0x20 записи, С))) — приказ натиска на этого бойца. Предел
  max(1, бойцов × 1,0) — все. Параметр приказа 0 / 10 / 2 (по типу бойца +0x104 и `14303425c`) — смысл не выяснил.
- Итого по бегущему: тот же темп «удар в интервал», но без парных схваток (нужен взгляд друг на друга), без прерываний
  от ответных ударов (бегущий не бьёт), шанс выше (тыл + натиск), урон выше (натиск).

## 4. Сколько бьют одного — В (код), С (смысл режимов)
- **Выбор цели бойцом** (`14308d10c`): предела нет (как в `melee_module.md` 2.4).
- **Счётчик** +0xa60 у бойца-цели: число задач, нацеленных на него (+1/−1 при смене цели задачи, `14307d5c0`).
- **Приказ атаки** раздаёт бойцам цели (`14327c350` → `1432781b8`): цель принимается, если предел < 0 или
  счётчик ≤ предела. Предел: по умолчанию **−1 (нет)**; 1 — в особом режиме (бит 4 поля +0x54 поведения, его ставят
  `1432885d0` / `1432885a0` при поле отряда +0x3e30 и условии `143014e20` — что это за режим, не выяснил, С/Н);
  4 — в `143288918` в том же режиме.
- Отдельная подсистема `142f6be48` → `142f6bc58` (по всей видимости, «подчинённые» бойцы, Н) берёт врага с
  **менее чем 6** нацеленными, предпочитая менее занятых (75 %).
- Для крупных моделей отдельного числа слотов в прочитанном коде нет; ограничение — только тела (столкновения) и
  досягаемость r₁ + 2,5 м × масштаб + r₂.
- Вывод: для пешего лорда в обычном бою жёсткого предела нет; «4–5 в 2,5 м» в зонде — геометрия и столкновения.

## 5. Край карты — В (ход), С (откуда границы)
- Границы — прямоугольник в объекте боя (+0x440 боя): x_min +0xd0, z_min +0xd4, x_max +0xd8, z_max +0xdc. Откуда
  берутся (вероятно, игровая область карты, `playable_area`) — не прослеживал (С).
- Каждый тик обновления бойца (`1430592bc`): если центр бойца за прямоугольником (x < x_min, z < z_min, x ≥ x_max или
  z ≥ z_max):
  - отряд «уходит с поля» (+0x3258 = 2) и боец ещё не ушёл → **боец уходит** (слот 0x448 `1430696c8`): событие
    «боец ушёл» (`Unit Left Battlefield`), снят со списков отряда (`143041a00`), приказ идти 5000 м наружу через
    ближайший край (`14302ff5c`), флаг «ушёл» (+0xb13 бит 3). **Не убит**: здоровья не теряет, в убитых не считается.
  - отряд не уходит → боец останавливается (слот 0x450 `143069754`: задачи сброшены).
- «Уходит с поля» = бежит (`1430348f0`) или текущий приказ — отход (слот 200 приказа) (`14301d1c0`); ставится в
  тике отряда (`14304bef8`), если нет флага +0x3e9c бит 2. Бегущий отряд получает его **сразу при бегстве**, а не у края.
- Когда ушёл последний боец, отряд снимается с поля; код итога (`14303e8d8`, запись +0x68 → +0xe4): 2 — «ушёл бегущим»,
  1 — «отошёл по приказу», 0 — уничтожен, 3 — особый случай (+0x3eb4), 5 — на поле.
