# Правила проекта

ИИ для сражений Total War: WARHAMMER III: симулятор на PyTorch (`tools/nn/sim`), обучение PPO
(`tools/nn/train`), уровни сети отряд → тактик → оперативник (`tools/nn/unit`, `tools/nn/tactic`), мост на Lua и
помощник в Docker, который играет в настоящую игру, пробы и проверки в игре. Документация: `docs/ru` (главная).
Главная сессия (оркестратор) решает, запускает обучение и коммитит; агенты делают задачи по письменному заданию.
Файл загружается при каждом запуске и после каждого сжатия контекста — у оркестратора и у всех агентов.

## Часть 1. Правила работы (от пользователя)

Эту часть меняют только с разрешения пользователя (правило 3). Правила — рамка, не инструкция: когда правило
мешает сделать лучше, его можно нарушить, сказав об этом одной строкой (правило 1).

1. **Результат важнее правил.** Любое правило, кроме 3 и раздела «Безопасность», можно нарушить ради качества и
   скорости — сразу написать, какое и почему: значит, правило надо поправить. Заметил формальность или трату
   токенов, которая тормозит, — сказать с предложением, как убрать.

2. **Просто и сразу по делу.** «Ты», короткие фразы, обычные слова, термин — объяснить в двух словах. Сначала
   главный вывод, потом детали. Числа — в таблице или строкой, не в тексте. Где схема понятнее слов — схема.

3. **Этот файл меняется только с разрешения пользователя**; после «да» — коммит и пуш.

4. **Соавтор, не исполнитель.** Видишь проблему или плохое решение (в том числе в просьбе пользователя) — сказать
   прямо, с причиной и альтернативой; решение — за пользователем. Просьбу читать по намерению: понять, чего он
   хочет добиться, и в 1–3 строках назвать подводные камни (цена, риск, конфликт с планом). Мелкие просьбы —
   просто делать. Перед запуском чего-то дорогого — одна строка: на какой вопрос отвечаем и какое число изменит
   решение.

5. **Оркестратор не делает задачи сам.** Чтение кода, анализ, правки, проверки, длинные выводы — агентам
   (только Opus, в каждом вызове `model: "opus"`), чтобы контекст не заполнялся. Сам: решения, задания, запуск
   обучения и боёв, короткие проверки статуса, правки в 1–3 строки, коммит и пуш. При этом вовлечён: читает
   отчёты, видит, когда агент не решил проблему, и сам придумывает следующий ход. Следующую задачу в той же
   области отдавать тому же агенту (продолжить его), нового — для другой области или независимой проверки.

6. **Один кодер на одни файлы.** Аналитики работают параллельно, код не трогают. Два кодера одновременно — только
   в разных пакетах, с явным разделением файлов, и сказать об этом. Обучение рядом с кодером — кодер в отдельной
   копии репозитория (worktree). Никогда два обучения сразу.

7. **Шаг обучения 5–40 минут**, метрики там, где они нужны для решения. Линию обучения не начинать самому:
   короткий отчёт с цифрами и предложением, решаем вместе. У задачи до старта — цель словами и страховка числами.

8. **Бои в игре — когда нужны, не впрок.** Каждый запуск обоснован: сколько боёв и на какой вопрос. Минимальный
   обязательный набор (рейтинг, золото пар, гибель лорда) держать всегда. Пробы для замеров механик агенты
   запускают сами.

9. **После сжатия контекста** читать: этот файл, память (сначала `project-current-state`), сводку `docs/ru/summary.md`;
   подробные разделы и страницы `design/*` — только по текущей задаче.

10. **Документация только `docs/ru`.** Английскую не трогать.

11. **Игровой режим** («игровой режим», «я играю» / выключает так же): видеокарта обучению 45 % (`--gpu-duty 0.45`),
    Docker 5 ядер, бои в игре не запускать, контейнеры на видеокарте остановить. Метка `build/steps/HUMAN_PLAYING`.

12. **Симулятор строго по игре.** Механики и числа — только из игры: программа игры (разбор Ghidra, memreader Plus), база игры, замеры в игре, сообщество.
    Ничего не придумывать и не подгонять множители: не сходится — искать, какой механики не хватает. Замеренное
    число — с записью, откуда и почему (`_why` в `config/nn/sim.json`). Известная дыра симулятора чинится до
    нового обучения. Судить сеть по боям в игре, не по рейтингу симулятора.

13. **Вход сети один в один.** Всё, что сеть получает в симуляторе, игра через мост даёт так же (поле, формула,
    нормировка), и наоборот. Новый вход / эффект / отряд — симулятор + мост + строка сети в одном задании;
    таблица `build/diag_g49/bridge_parity.md`. Карта местности снимается один раз, один в один.

14. **Что не делать без пользователя:** код тактика и выше (кроме входа, он уже в коде), сеть личного уровня
    (`tools/nn/unit/{view,zmap,net}.py`), страницы `design/*`, новые линии обучения, новые области работы.
    Автономно (нет задачи) — очередь отрядов `build/diag_roster/skaven_queue.md` и план дыр `build/diag_mem/plan.md`;
    аналитик — не больше чем на один отряд вперёд.

15. **Цель линии:** ИИ без глупостей стокового, не чемпион. Упражнение = защита от одной глупости, экзамен = список
    глупостей, рецепт воспроизводим; релиз модом, архитектура сообществу.

### Безопасность (не нарушается)
- Бои против ИИ игры — только «Нормальная», в игре только на RTX.
- `rm -rf` нигде; без `git reset --hard` и `git clean` в основной папке; пути в `rm` явно; ночью — команды, не
  требующие ручного разрешения.

## Часть 2. Технические правила (для агентов и оркестратора)

Оркестратор правит их сам и сообщает пользователю.

**Ресурсы**
- Один контейнер на агента (`DOCK_NAME=agent-<задача> bash tools/nn/dock.sh ...`), после агента — `docker ps`,
  контейнер остановлен. Память Docker 15,5 ГБ на всех: при обучении рядом не больше одного лёгкого контейнера.
- Пока идёт обучение или бой в игре — агенты на процессоре (`DOCK_CPUS=6`); видеокарта свободна — долгие
  прогоны на ней. Экзамен — на пустой машине. Пользователь играет — контейнеры на паузе / на видеокарте стоп.
- Пробы в игре: `BAI_GRAPHICS=low`, «Нормальная», максимальная скорость игры, 2–3 дорожки в одном бою, замок
  `build/steps/probe_game.lock`, не при `build/steps/HUMAN_PLAYING`; боёв — минимум для ответа, в отчёте сколько
  и зачем.
- Диск: кэш `tww3-torch-cache` и `build/` растут; чистить кэш от файлов старше 2 суток раз в неделю.
- Замок видеокарты `build/gpu-train.lock` ставит и снимает `run.py`; обучение останавливать
  `python -m tools.ops.leftovers --stop <имя>`, упавшее — `--unlock`.
- Поиск в интернете — только WebSearch/WebFetch, браузер агентам не открывать.
- Работающий bash-скрипт цепочки не править на месте: новая версия — новый файл.

**Копии репозитория (worktree)**
- Никаких ссылок (junction/symlink) на папки основной; Python копии — `../TWW3-batle-ai/.venv/Scripts/python`.
- Патч относительно СОБСТВЕННОЙ основы копии (`git add -A; git diff --cached HEAD`, `git apply --3way`), не
  `git diff main`. Копию удалять отдельной командой, только когда правки уже в коммите main.

**Обучение**
- Ветки способностей — половина доли; новые способности / новый исполнитель — 2 круга полная, потом половина.
- Базы скриптов не пересчитывать; смена версии симулятора — только сказать в отчёте.

**Границы задания агента**
- Менять только названное. Симулятор, награда, мост, протокол проверки — только если задание говорит; иначе
  предложение в отчёте. Числа — из базы игры прежде догадок. Новый вход сети — только из данных, что даёт игра;
  никогда время до конца боя.
- Агенты не коммитят. Данные анализа (json, csv, npz) не в git — только png/svg/md; свои файлы — в своей папке
  `build/diag_<задача>/`. Отчёт — последним сообщением, не файлом.

**Код, тесты, документация**
- Маленькие модули; каждое правило — тест. Хост: `.venv/Scripts/python -m pytest -q`; с torch — в контейнере.
- Документация описывает, как работает сейчас, правится на месте; неудачи — в «Пробовали и отказались» с
  числами, без хронологии. Новая страница — `python -m tools.docs.index_doc`. Правка, меняющая устройство или
  главные цифры, обновляет `docs/ru/summary.md`.

**Отчёт агента**: первая строка — задача своими словами и направление метрики; реальное время; что изменено;
что и как проверено; что не сделано. До ~300 слов, простым языком.

**Инструменты оркестратора** (`tools/ops`, подробно `docs/ru/training/workflow.md`): `step` (команда шага),
`card` (карточка итогов), `leftovers` (что висит). Коммит: `git add -A -- . ':!nul'`, хук ~10 мин, в фоне.
